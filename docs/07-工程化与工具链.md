# 07 · 工程化与工具链

> 读完本章你会掌握:这个"没有 build step"的仓库,是靠哪几个脚本 + git hook + CI 维系质量的。演进前必须能熟练跑这条纪律链。

## 7.1 全景:一条纪律链取代"构建"

因为没有编译,仓库用一套脚本 + hook + CI 来保证一致性:

```
 编辑 .md / manifest
      │
      ▼
 sync-agent-skills.py   ← 把 vertical skill 源同步进 agent bundle
      │
      ▼
 check.py               ← 校验一切:frontmatter / 引用 / drift / marketplace(提交前必跑)
      │
      ▼
 git commit ─pre-commit─▶ version_bump.py --apply(自动 patch-bump 版本)
      │
      ▼
 push / PR ─CI─▶ version-bump --check + secret-scan + (china-market 改动→出镜像)
```

## 7.2 `scripts/` 逐个说明

| 脚本 | 干什么 | 何时跑 |
|---|---|---|
| **check.py** | 提交前必跑的 linter,顺带自装 git hook | 每次提交前 |
| **sync-agent-skills.py** | 把 vertical skill 源 `copytree` 到 agent bundle | 改完 skill 后 |
| **version_bump.py** | 版本自增(`--apply` 改、`--check` 校验) | hook / CI 自动 |
| **deploy-managed-agent.sh** | 把 cookbook 部署成 `POST /v1/agents` | 部署 managed agent 时 |
| **validate.py** | 用 jsonschema 校验 subagent 输出 | 部署 / 运行时 |
| **orchestrate.py** | 跨 agent handoff 事件循环(参考实现) | 仅参考 |
| **test-cookbooks.sh** | 对每个 cookbook 跑 `--dry-run` 断言 | 改 cookbook 后 |

### check.py —— 最重要的脚本

它做 5 类校验(见 [check.py:5-12](../scripts/check.py#L5-L12) 的 docstring):

1. `managed-agent-cookbooks/` 下每个 `.yaml` 能解析([check.py:69-75](../scripts/check.py#L69-L75));
2. 每个 `plugin.json`/`marketplace.json`/`steering-examples.json` 能解析([:77-89](../scripts/check.py#L77-L89));
3. 每个 `agents/*.md` 有合法 frontmatter(含 `name`+`description`,[:91-105](../scripts/check.py#L91-L105));
4. `agent.yaml`/subagent 里的 `system.file` / `skills.path` / `callable_agents.manifest` 引用都能解析([:108-140](../scripts/check.py#L108-L140));**且 agent bundle 的 skill 与 vertical 源无 drift**([:142-159](../scripts/check.py#L142-L159));
5. 每个 cookbook 目录有 `agent.yaml`/`README.md`/`steering-examples.json`([:180-186](../scripts/check.py#L180-L186))。

还有两个附加校验:agent.md 里反引号引用的 skill 必须真的被 bundle([:161-171](../scripts/check.py#L161-L171));marketplace 每个 source 路径下有 `plugin.json`([:173-178](../scripts/check.py#L173-L178))。

**副作用**:它在做任何可能提前退出的事(如缺 pyyaml)之前,先 `git config core.hooksPath .githooks` 把 hook 装上([check.py:27-51](../scripts/check.py#L27-L51))——所以新克隆的人只要跑过一次 check.py,version-bump hook 就自动生效了。

运行:

```bash
cd financial-services
python3 scripts/check.py      # OK 或列出所有问题并 exit 1
```

### sync-agent-skills.py 与 drift

skill 源在 vertical,agent bundle 是副本。改完源必须跑:

```bash
python3 scripts/sync-agent-skills.py
```

否则 check.py 第 4 类校验会用 `filecmp.dircmp` 判定 bundle "drifted",提交被拦。这是"单一源同步"理念(见 [03](./03-核心设计理念.md))的执行者。

### version_bump.py —— 版本单一真源

- `--apply`(pre-commit 用):把有改动的插件 patch-bump 到比 base **领先恰好一位**,幂等(一个分支只 bump 一次)。
- `--check`(CI 用):校验版本是否符合规则,不改文件。

版本号 gate 更新投递,所以任何插件改动都要 bump,这条由 hook + CI 双保险(见 [CLAUDE.md:33](../CLAUDE.md#L33))。想跳过某次:`git commit --no-verify`。

### deploy-managed-agent.sh / validate.py / orchestrate.py

这三个服务于 Managed Agent(细节见 [05](./05-Managed-Agent与编排.md)):

- `deploy-managed-agent.sh <slug>`:解析 `{file:}`/`{path:}` 引用、内联 system、上传 skill、递归建 subagent、POST orchestrator;支持 `--dry-run`。需要 `ANTHROPIC_API_KEY`,可选 `ANTHROPIC_API_BASE` / `SKILL_TITLE_PREFIX` / `DEPLOY_DEBUG`。
- `validate.py`:用 jsonschema 按 subagent 的 `output_schema` 校验 worker 输出(reader 的强隔离靠它落地)。
- `orchestrate.py`:handoff 事件循环参考实现(REFERENCE ONLY),含 prompt-injection 缓解(target allowlist + schema 校验)。

## 7.3 测试现状(没有统一框架)

**没有 pytest 配置、没有覆盖率工具**。测试是两处定制脚本:

| 测试 | 覆盖什么 | 怎么跑 |
|---|---|---|
| `china-market/test_data_layer.py` | 用 synthetic `FakeSource` **无网络确定性**验证:双写一致/分歧、熔断器熔断+半开、web_fallback、有序 fallback、TTL 缓存、`DictCache` 注入证明缓存可替换 | `python test_data_layer.py`(需含 mcp 的环境) |
| `scripts/test-cookbooks.sh` | 对每个 cookbook 跑 `deploy --dry-run`,断言:system 非空、depth ≤ 1(子 agent 不能再有 callable_agents)、无 output_schema 泄漏 | `scripts/test-cookbooks.sh` |

对 markdown/manifest 而言,`check.py` 就充当"测试"。

## 7.4 Git hook 与 CI

**Git hook**:`.githooks/pre-commit` → 调 `version_bump.py --apply`。由 check.py 自动接线(`core.hooksPath`),无 Husky / Node。

**CI**(`.github/workflows/`,三条):

| Workflow | 触发 | 作用 |
|---|---|---|
| `china-market-image.yml` | `mcp_server/**` 变化 | 用 `docker/build-push-action` 把镜像发到 GHCR(`ghcr.io/<owner>/china-market-mcp`,tag latest/sha/china-market-vX.Y.Z) |
| `version-bump.yml` | PR | 跑 `version_bump.py --check`,给没装本地 hook 的贡献者兜底 |
| `secret-scan.yml` | push / PR | gitleaks(pinned SHA + sha256 校验)+ 自定义 grep 扫内部 Anthropic 引用 |

> 关键含义:**services 仓既是 china-market 的代码源,也是镜像源**。你改 `mcp_server/`,CI 自动出新镜像,下游只 pull——所以别在下游维护拷贝(见 [01](./01-项目全景与定位.md) 1.8)。

## 7.6 配置与密钥约定

- `.gitignore` 忽略 `.env*` / `*.key` / `*.pem` / `TASKS.md` / `MEMORY.md`。
- 用户私有配置用 `*.local.md`(gitignored,见 [CLAUDE.md:41](../CLAUDE.md#L41))。
- secret 由 `secret-scan.yml` CI 兜底扫描。
- china-market 的 tushare token 走 `config.yaml` 或 `TUSHARE_TOKEN` env,**绝不硬编码进代码**。
