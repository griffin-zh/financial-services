# 09 · 验证、约定与常见陷阱

> 最后一章:把最容易踩的坑集中列出,配一份可照做的验证清单。改动这个仓库前后,对照本章能帮你避开 90% 的返工。

## 9.1 提交前验证清单

```bash
cd financial-services

# ① 若动了 skill 源:先同步再校验
python3 scripts/sync-agent-skills.py

# ② 必跑:全量校验(frontmatter / 引用 / drift / marketplace / cookbook)
python3 scripts/check.py
#   期望输出:OK — N file(s) checked, 0 issues.

# ③ 若动了 china-market 代码:无网络确定性测试
python plugins/partner-built/china-market/test_data_layer.py

# ④ 若动了 managed-agent cookbook:dry-run 部署断言
scripts/test-cookbooks.sh

# ⑤ 提交(pre-commit 自动 patch-bump 版本)
git commit -m "..."
```

对本指南书自身的验证(本次新增 `docs/` 只是文档):`python3 scripts/check.py` 应仍然 `OK`——因为新增 `docs/` 不触及任何 manifest / 引用 / drift 校验路径。

## 9.2 常见陷阱清单

### 陷阱 1:直接改了 agent bundle 里的 skill 副本 → drift

**症状**:check.py 报 `bundled-skill: … drifted from … (run scripts/sync-agent-skills.py)`。
**根因**:你改了 `plugins/agent-plugins/<slug>/skills/…`,而它是副本。
**正解**:改 `plugins/vertical-plugins/<vertical>/skills/…` 源,再 `python3 scripts/sync-agent-skills.py`(见 [03](./03-核心设计理念.md) 3.2、[check.py:146-159](../scripts/check.py#L146-L159))。

### 陷阱 2:改了插件却没 bump 版本 → 用户收不到更新

**根因**:`version` gate 更新投递,不变就不推送。
**正解**:通常**不用手动管**——pre-commit hook 会自动 patch-bump。前提是你跑过一次 `check.py`(它会自装 hook)。若在没装 hook 的环境提交,CI `version-bump.yml` 会拦你。别手动乱改 version(见 [03](./03-核心设计理念.md) 3.3)。

### 陷阱 3:china-market 代码里用了 `print` → 静默破坏 MCP 协议

**根因**:MCP 用 **stdout** 传协议,任何往 stdout 的打印都会污染它(见 [sources.py:14-16](../plugins/partner-built/china-market/mcp_server/sources.py#L14-L16))。
**正解**:数据源库调用统一套 `_silence_stdout`([sources.py:74-82](../plugins/partner-built/china-market/mcp_server/sources.py#L74-L82));你自己的日志走 `loguru` → stderr([server.py:44-45](../plugins/partner-built/china-market/mcp_server/server.py#L44-L45))。**新增任何打印都必须走 stderr**。

### 陷阱 4:误解 confidence 语义

- 双写 `high` 需要 **≥2 源且 pct_chg 一致**;只有 1 源永远是 `single`(降级),不是 `high`。
- 多 symbol 的 `get_daily_bars` 取**最差** confidence(`stale < low < single < high`,[server.py:205-206](../plugins/partner-built/china-market/mcp_server/server.py#L205-L206))——一个 symbol 弱,整体就弱。
- 上层生成报告时,遇到 `degraded`/`low`/`stale` 要显式标注,不能当 high 用。

### 陷阱 5:数据源全挂时"静默返回空"

**正解**:不要静默空。路由层已设计成返回 `web_fallback=True` 的结构化 surface([sources.py:579-592](../plugins/partner-built/china-market/mcp_server/sources.py#L579-L592)),上层按**白名单**([WEB_FALLBACK_WHITELIST.md](../plugins/partner-built/china-market/references/WEB_FALLBACK_WHITELIST.md))web-fetch 并标来源 + 口径。连不上服务时先查服务是否在跑、端口是否发布,别直接 fallback(见 [CLAUDE.md:80](../CLAUDE.md#L80))。

### 陷阱 6:跨市场做了隐式汇率换算

**正解**:A 股(CNY)与美股(USD)**币种分开列,不做隐式换算**(见 [CLAUDE.md:67](../CLAUDE.md#L67))。A 股估值要用 `get_market_context` 给的中国特化输入(CNY / 中国 10Y risk-free / China ERP / 25% 税率 / 申万行业 / 巨潮 filings,见 [server.py:318-346](../plugins/partner-built/china-market/mcp_server/server.py#L318-L346)),别照搬美股假设。

### 陷阱 7:在下游 `financial-product/` 改了 china-market 代码

**正解**:china-market 的**单一源在 `financial-services/.../mcp_server/`**,CI 出镜像,下游只 pull。改代码永远在 services 仓(见 [CLAUDE.md:66](../CLAUDE.md#L66)、[01](./01-项目全景与定位.md) 1.8)。

### 陷阱 8:新增 agent 只做了一半(漏了 cookbook 或 marketplace 登记)

**正解**:新增具名 agent 是"三处 + 一登记"(agent-plugin + cookbook + marketplace,见 [08 场景 3](./08-如何修改与演进.md))。check.py 会因 marketplace source 无 plugin.json、或 cookbook 缺三件套而报错。

## 9.3 安全约定(演进时守住的线)

- **产品边界**:agent 只产"待人签字的草稿",不执行交易 / 过账 / 审批(见 [01](./01-项目全景与定位.md) 1.6、[README.md:7-8](../README.md#L7-L8))。加新 agent 时守住同一条线。
- **不可信输入隔离**:任何读外部 / 对手方文件的子 agent,照 `reader.yaml` 范式——无写权限、无 MCP、声明 UNTRUSTED、输出过 JSON Schema(限长 + 限字符集),见 [05](./05-Managed-Agent与编排.md) 5.4。
- **密钥**:`.gitignore` 忽略 `.env*`/`*.key`/`*.pem`;tushare token 走 config / env,绝不硬编码;CI `secret-scan.yml`(gitleaks)兜底。
- **`${VAR}` 注入**:Managed Agent 的 url 占位有字符白名单 `[A-Za-z0-9._/:@-]` 防注入(见 [05](./05-Managed-Agent与编排.md) 5.3)。

## 9.4 商用 License 红线(演进到多用户 / 商用前必读)

仓库主体是 Apache-2.0,但 **china-market 依赖的数据源不受它覆盖**:

- **tushare Pro**:需 token,有积分 / 商用条款;
- **akshare / baostock**:各有使用条款;
- **11 个第三方数据 MCP**(Daloopa/FactSet/Kensho/Moody's/PitchBook…):各需订阅 / API key,数据再分发受限。

演进到"给多个用户提供服务"或商用前,**必读** [DATA_SOURCES.md](../plugins/partner-built/china-market/references/DATA_SOURCES.md) 里的选型说明、100 用户架构蓝图与**商用 license 红线**,确认合规。

## 9.5 一页速查(贴在手边)

| 要点 | 记住 |
|---|---|
| 改 skill | 改 vertical 源 → `sync-agent-skills.py` → `check.py` |
| 改 agent 行为 | 只改 `agents/<slug>.md`,两形态共享 |
| 版本 | 别手动改,让 pre-commit hook 自动 bump |
| 提交前 | 永远先 `python3 scripts/check.py` |
| china-market | 加源=新 `DataSource` 子类;加 tool=新 `@mcp.tool()`;换缓存=新 `Cache` 子类 |
| stdout | china-market 里任何打印走 stderr |
| 数据可信度 | 看 confidence/degraded/web_fallback,别当 high 用 |
| 币种 | A 股 CNY 与美股 USD 分列,不隐式换算 |
| 安全 | 产草稿不执行;不可信输入照 reader 隔离;密钥走 env |
| 单一源 | china-market 代码只在 services 仓改,下游 pull 镜像 |
