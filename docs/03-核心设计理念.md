# 03 · 核心设计理念(全书的钥匙)

> 这一章讲的是四条**贯穿全仓的约定**。它们不是代码里能"读"出来的,而是靠脚本 + CI + git hook 强制维系的。理解了它们,你才敢改这个仓库而不把它改坏。

## 3.1 理念一:一源两包装(One Source, Two Wrappers)

**问题**:同一个 agent(比如 GL Reconciler)既要能在 Cowork/Claude Code 里当插件用,又要能通过 API 托管部署。如果两边各写一份系统提示词,迟早会不一致。

**解法**:系统提示词只写一份,两种形态都**引用**它。

```
      plugins/agent-plugins/gl-reconciler/agents/gl-reconciler.md   ← 唯一权威系统提示词
                    ▲                                    ▲
   插件形态直接用它                         cookbook 用 system.file 相对路径回指
                                    managed-agent-cookbooks/gl-reconciler/agent.yaml:11
```

证据([agent.yaml:10-12](../managed-agent-cookbooks/gl-reconciler/agent.yaml#L10-L12)):

```yaml
system:
  file: ../../plugins/agent-plugins/gl-reconciler/agents/gl-reconciler.md
  append: "You are running headless. Produce files in ./out/; ..."
```

注意 `append`:托管部署时会在同一份提示词后**追加** headless 专属指令(如"在 ./out/ 产文件,别假设有打开的 Office 文档")。这样"共享大脑 + 各自环境微调"两不误。

> **演进含义**:改 agent 的人格 / 工作流,永远改 `agents/<slug>.md`,两种形态同时生效。永远不要把提示词内容抄进 `agent.yaml`。

## 3.2 理念二:单一源同步(Skill 的源与副本)

**问题**:一个 skill(比如 `dcf-model`)既属于 `financial-analysis` 垂直,又要被 `model-builder`、`pitch-agent` 等多个 agent 打包携带。多处拷贝同样会漂移。

**解法**:**源只有一处,副本靠脚本同步,靠 CI 禁止手改副本**。

```
plugins/vertical-plugins/<vertical>/skills/<name>/   ← 唯一源(在这里改)
              │  python3 scripts/sync-agent-skills.py(shutil.copytree 传播)
              ▼
plugins/agent-plugins/<slug>/skills/<name>/          ← vendored 副本(禁止手改)
```

`scripts/check.py` 会用 `filecmp.dircmp` 逐目录比对源与副本,一旦发现 `diff_files / left_only / right_only` 就**报错并要求你重跑 sync**(见 [check.py:146-159](../scripts/check.py#L146-L159)):

```python
cmp = filecmp.dircmp(src, bundled)
if cmp.diff_files or cmp.left_only or cmp.right_only:
    err(f"bundled-skill: {rel(bundled)}: drifted from {rel(src)} (run scripts/sync-agent-skills.py)")
```

> **最常见的坑**:直接编辑了 `agent-plugins/.../skills/` 里的副本 → CI 判 drift、提交被拦。正确姿势永远是"改 vertical 源 → 跑 sync"。见 [09](./09-验证约定与常见陷阱.md)。

## 3.3 理念三:版本门控(Version Gates Update Delivery)

**问题**:插件已经被用户安装了,你改了它,怎么让用户收到更新?

**解法**:每个插件的 `plugin.json` 里有个 `version`(语义化 `x.y.z`)。**这个版本号 gate 更新投递**——只有版本号变了,已安装用户才会收到新版本。所以"任何插件改动都必须 bump 版本"是硬约束。

为了不让你手动记这件事,仓库用**双保险自动化**(见 [CLAUDE.md:33](../CLAUDE.md#L33)):

1. **pre-commit hook**(`.githooks/pre-commit` → `scripts/version_bump.py --apply`):提交时自动把有改动的插件 patch-bump 到比 `main` 领先**恰好一位**(幂等——一个分支只 bump 一次,不是每次 commit 都加)。
2. **CI backstop**(`.github/workflows/version-bump.yml` → `version_bump.py --check`):给没装本地 hook 的贡献者兜底,PR 上强制同一规则。

hook 是怎么装上的?你**不用手动装**——`check.py` 首次运行时会 `git config core.hooksPath .githooks` 自把 hook 接上(原生替代 Husky,见 [check.py:27-51](../scripts/check.py#L27-L51))。

> 想跳过某次 commit 的自动 bump:`git commit --no-verify`。但正常情况下让它自动跑。

## 3.4 理念四:file-based / no build step

没有编译、没有打包产物(china-market 镜像除外)。改 `.md` 即刻生效([README.md:99](../README.md#L99),[CLAUDE.md:46-48](../CLAUDE.md#L46-L48)):

> 1. Edit markdown files directly - changes take effect immediately
> 2. Test commands with `/plugin:command-name` syntax
> 3. Skills are invoked automatically when their trigger conditions match

心智模型:**你在"写规范",不是"写程序"**。交付单元是 plugin;"构建"这件事被 `check.py`(校验)+ `sync`(同步)+ `version_bump`(版本)这条纪律链取代。

## 3.5 贯穿始终的命名约定:slug 四处一致

一个具名 agent 的 slug(kebab-case,如 `gl-reconciler`)必须在四个地方**完全一致**,`check.py` 靠这个一致性把它们关联起来:

| 位置 | 例子 |
|---|---|
| agent-plugin 目录名 | `plugins/agent-plugins/gl-reconciler/` |
| marketplace.json 的 `name` | `"name": "gl-reconciler"`([marketplace.json:68](../.claude-plugin/marketplace.json#L68)) |
| `agents/<slug>.md` frontmatter 的 `name` | `name: gl-reconciler` |
| cookbook 目录名 | `managed-agent-cookbooks/gl-reconciler/` |

各种 manifest 的 frontmatter 契约(`check.py` 会校验):

- **SKILL.md** → frontmatter 必须有 `name` + `description`(`description` 承载**触发语义**,见 [dcf-model/SKILL.md:1-4](../plugins/vertical-plugins/financial-analysis/skills/dcf-model/SKILL.md#L1-L4))
- **command.md** → frontmatter 必须有 `description` + `argument-hint`
- **agents/<slug>.md** → frontmatter 必须有 `name` + `description`(见 [check.py:91-105](../scripts/check.py#L91-L105))

## 3.6 一张图记住四条理念如何协作

```
    你改了东西
        │
        ├─ 改 skill?    → 只改 vertical 源 ──sync──▶ 副本(理念二)
        ├─ 改 agent?   → 只改 agents/<slug>.md,两形态共享(理念一)
        ├─ 改 .md?     → 立即生效,无需构建(理念四)
        │
        ▼
   python3 scripts/check.py   ← 校验:frontmatter / 引用 / drift / marketplace
        │
        ▼
   git commit  ──pre-commit hook──▶ version_bump 自动 patch-bump(理念三)
        │
        ▼
   push / PR  ──CI──▶ 再次 check + version-check + secret-scan
```
