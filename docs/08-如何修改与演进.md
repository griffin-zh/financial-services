# 08 · 如何修改与演进(操作手册)

> 这是本书面向未来的核心章。每一节都按同一模板给你:**改哪些文件 → 跑哪些脚本 → 怎么验证**。照做就不会破坏仓库的约定。
>
> 通用收尾(几乎每个场景都一样):`python3 scripts/check.py` 通过 → `git commit`(pre-commit 自动 bump 版本)→ push。下文不再重复这句,除非有额外动作。

---

## 场景 1 · 改 / 加一个 Skill

**改哪些文件**:只改 vertical 源 `plugins/vertical-plugins/<vertical>/skills/<name>/SKILL.md`。
- 新建 skill:建目录 + `SKILL.md`,frontmatter 必须有 `name` + `description`(`description` 里写清"Use when …"触发条件,这是 skill 能否被自动激活的关键,见 [04](./04-插件与Skill体系.md) 4.2)。
- 可选:`references/`、`requirements.txt`。

**跑哪些脚本**:
```bash
python3 scripts/sync-agent-skills.py   # 把源同步进所有 bundle 了它的 agent
python3 scripts/check.py               # 校验 + 确认无 drift
```

**怎么验证**:check.py 输出 `OK`;在 Claude Code 里用触发场景的话术,确认 skill 自动激活;若有对应 command,用 `/plugin:command` 试。

> ❌ 最常见错误:直接改了 `agent-plugins/<slug>/skills/` 里的副本。那会被判 drift。永远改 vertical 源再 sync。

## 场景 2 · 改一个 Slash Command

**改哪些文件**:`plugins/vertical-plugins/<vertical>/commands/<name>.md`,frontmatter 需 `description` + `argument-hint`。

**验证**:`python3 scripts/check.py`;在会话里敲 `/<plugin>:<command>` 试。

## 场景 3 · 新增一个具名 Agent

这是"跨三处 + 一登记"的完整流程,务必四步都做,保证一源两包装一致。

**改哪些文件**:
1. `plugins/agent-plugins/<slug>/`
   - `.claude-plugin/plugin.json`(name/version/description/author)
   - `agents/<slug>.md`(**权威系统提示词**,frontmatter `name`+`description`;`name` 与 slug 一致)
   - `skills/`(从 vertical sync 进来的副本,别手写)
2. `managed-agent-cookbooks/<slug>/`
   - `agent.yaml`(`system.file` 相对路径回指上面的 `agents/<slug>.md`;tools 最小权限;需要子 agent 就加 `callable_agents`)
   - `subagents/*.yaml`(depth-1 叶子 worker,读不可信输入的要照 reader 范式隔离,见 [05](./05-Managed-Agent与编排.md) 5.4)
   - `steering-examples.json` + `README.md`(安全 tier + handoff 说明)
3. 登记 `.claude-plugin/marketplace.json`(加一条 `{name, source, description}`,source 指向 agent-plugin 目录)

**跑哪些脚本**:
```bash
python3 scripts/sync-agent-skills.py
python3 scripts/check.py        # 校验 frontmatter / 引用 / marketplace source / cookbook 三件套
scripts/test-cookbooks.sh       # 校验 cookbook 能 dry-run 部署、depth ≤ 1
```

**怎么验证**:check + test-cookbooks 全绿;`scripts/deploy-managed-agent.sh <slug> --dry-run` 解析出合法的 `POST /v1/agents` body。

> 参照现成样板:`gl-reconciler`(带三个子 agent + 安全隔离)是最完整的模板。

## 场景 4 · 改 Agent 的行为 / 人格

**改哪些文件**:只改 `plugins/agent-plugins/<slug>/agents/<slug>.md`。因为一源两包装,插件形态与 Managed Agent 形态**同时生效**,无需改 `agent.yaml`。

**验证**:`python3 scripts/check.py`(frontmatter 仍合法);在 Cowork/Claude Code 里跑该 agent 观察行为。

## 场景 5 · 换 / 加一个数据连接器(第三方 MCP)

**改哪些文件**:对应插件的 `.mcp.json`。核心 11 个连接器集中在 [financial-analysis/.mcp.json](../plugins/vertical-plugins/financial-analysis/.mcp.json),在 `mcpServers` 里加/改一条 `{ "type": "http", "url": "…" }`。

**验证**:`python3 scripts/check.py`(JSON 可解析);在会话里 `/mcp` 看连接器状态;因为核心 skill 是**软引用** MCP(见 [04](./04-插件与Skill体系.md) 4.3),接入后无需改 skill。

> 想接你公司内部数据源?把 url 指向你自己的 MCP server 即可(见 [README.md:154](../README.md#L154))。

## 场景 6 · 给 china-market 加一个数据源

这是抽象基类设计要回报你的地方——**加源不动上层**。

**改哪些文件**:
1. `plugins/partner-built/china-market/mcp_server/sources.py`:
   - 新增一个 `class MySource(DataSource)`,设 `name`、`capabilities`,实现你支持的 `fetch_*` 方法,**输出 rename 到 `DAILY_COLUMNS`**(见 [sources.py:112-141](../plugins/partner-built/china-market/mcp_server/sources.py#L112-L141) 抽象 + [:144](../plugins/partner-built/china-market/mcp_server/sources.py#L144) akshare 范例)。
   - 在 `build_router`([:629-650](../plugins/partner-built/china-market/mcp_server/sources.py#L629-L650))里按 config 开关把它 append 进 sources 列表。
2. `mcp_server/config.yaml`:在 `sources:` 下加你的源开关(+token 若需要)。

**跑哪些脚本 / 验证**:
```bash
python plugins/partner-built/china-market/test_data_layer.py   # 无网络确定性测试仍全绿
# 本地起服务冒烟
MCP_TRANSPORT=sse MCP_PORT=8080 python plugins/partner-built/china-market/mcp_server/server.py
```
提交后 CI(`china-market-image.yml`)会因 `mcp_server/**` 变化**自动出新镜像**。

> ⚠️ 新代码里任何打印必须走 stderr(stdout 纪律,见 [06](./06-china-market代码走读.md) 6.10);新源的失败要 raise `SourceError`,让 router 计入熔断。

## 场景 7 · 给 china-market 加一个 MCP tool

**改哪些文件**:`mcp_server/server.py`,加一个 `@mcp.tool()` 装饰的函数:
- 双写平面(数据应跨源一致)→ 调 `_router.get_xxx` 后用 `_pack_dual` 打包([server.py:113](../plugins/partner-built/china-market/mcp_server/server.py#L113));
- 单源 / 特色平面 → 用 `_pack_single`([:129](../plugins/partner-built/china-market/mcp_server/server.py#L129));
- 保持**统一返回体**字段(rows/count/columns/sources/confidence/degraded/discrepancy/warnings/web_fallback),上层 skill 才能感知降级。

若 tool 需要新数据能力,先在 sources 侧加对应 `fetch_*` + router 的 `get_*`(见场景 6)。

**验证**:起服务后 `/mcp` 里能看到新 tool;`test_data_layer.py` 全绿。

## 场景 8 · 缓存 / 存储升级(如换 Redis / Postgres)

这是 `cache.py` 注释里**文档化的演进蓝图**([cache.py:1-7](../plugins/partner-built/china-market/mcp_server/cache.py#L1-L7))。

**改哪些文件**:
1. `mcp_server/cache.py`:实现 `class RedisCache(Cache)`,实现 `get` / `set` 两个抽象方法(照 [InMemoryTTLCache:32-58](../plugins/partner-built/china-market/mcp_server/cache.py#L32-L58) 的形状)。
2. `mcp_server/server.py`:改注入点 [:68-69](../plugins/partner-built/china-market/mcp_server/server.py#L68-L69) 两行,把 `LocalParquetCache` / `InMemoryTTLCache` 换成你的实现。**tool 逻辑一行不动**。

**验证**:`test_data_layer.py` 里已有的 `DictCache` 注入测试证明了接口可替换性——你的新实现只要通过同样的 get/set 契约即可。进一步可把"请求时拉"改成后台 IngestionJob"定时入库"(见蓝图 [DATA_SOURCES.md](../plugins/partner-built/china-market/references/DATA_SOURCES.md))。

## 场景 9 · 加一个自动化 Hook

**改哪些文件**:对应插件的 `hooks/hooks.json`(当前多为空 `[]`,是现成挂点,见 [04](./04-插件与Skill体系.md) 4.4)。按 Claude Code hook 规范填事件 + 命令。

## 提交前 Checklist(所有场景通用)

```bash
# 1) 若动了 skill 源
python3 scripts/sync-agent-skills.py
# 2) 必跑
python3 scripts/check.py                    # 期望: OK — N file(s) checked, 0 issues.
# 3) 若动了 china-market
python plugins/partner-built/china-market/test_data_layer.py
# 4) 若动了 cookbook
scripts/test-cookbooks.sh
# 5) 提交(pre-commit 自动 patch-bump 版本;别手动改 version)
git commit -m "..."
```

- ✅ 让 pre-commit hook 自动 bump 版本,不要手动改 `plugin.json` 的 `version`。
- ✅ 改 skill 走"vertical 源 → sync",绝不手改 bundle 副本。
- ✅ 改 agent 行为改 `agents/<slug>.md`,不碰 `agent.yaml` 的提示词。
- ✅ 改 china-market 代码,守住 stdout 纪律 + license 红线(见 [09](./09-验证约定与常见陷阱.md))。
