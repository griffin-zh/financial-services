# 02 · 仓库结构与目录地图

> 读完本章你会拿到:一张带注解的目录地图,和一张"我要改 X 该去哪"的速查表。这是你日后翻得最多的一章。

## 2.1 顶层布局(三分法)

以 [README.md:38-46](../README.md#L38-L46) 与 [CLAUDE.md:5-29](../CLAUDE.md#L5-L29) 为准:

```
financial-services/
├── .claude-plugin/marketplace.json   # 插件注册中心:登记全部 21 个插件的 source 路径
├── .githooks/pre-commit              # 提交时自动 patch-bump 版本(替代 Husky)
├── .github/workflows/                # 3 条 CI:出镜像 / 版本校验 / secret 扫描
├── CLAUDE.md  README.md  user_guide.md  LICENSE
│
├── plugins/                          # ← 能力主体,三类
│   ├── vertical-plugins/<vertical>/  #   ① 按 FSI 垂直组织:skill 的【唯一源】+ command + 连接器
│   │   ├── .claude-plugin/plugin.json
│   │   ├── commands/*.md             #     slash command
│   │   ├── skills/<name>/SKILL.md     #     skill 权威源
│   │   ├── .mcp.json                  #     数据连接器
│   │   └── hooks/hooks.json           #     Claude Code hook 挂点(当前多为空 [])
│   │
│   ├── agent-plugins/<slug>/         #   ② 10 个具名 agent:自包含插件
│   │   ├── .claude-plugin/plugin.json
│   │   ├── agents/<slug>.md          #     ← 权威系统提示词(一源两包装的"源")
│   │   └── skills/                    #     ← 从 vertical 同步来的【副本】(禁止手改)
│   │
│   └── partner-built/                #   ③ 合作方插件
│       ├── lseg/  spglobal/           #     纯 skill/connector 形态
│       └── china-market/              #     ← 全仓唯一含真实运行代码
│           ├── mcp_server/            #       server.py / sources.py / cache.py / config.yaml
│           ├── skills/                #       3 个中国市场上下文 skill
│           ├── references/            #       DATA_SOURCES.md / WEB_FALLBACK_WHITELIST.md
│           └── data_cache/            #       本地 parquet 缓存(历史日线)
│
├── managed-agent-cookbooks/<slug>/   # ← 同一批 agent 的【托管部署包装】
│   ├── agent.yaml                    #   system 引用 agent-plugins 的提示词 + tools + MCP + skills
│   ├── subagents/*.yaml              #   depth-1 叶子 worker
│   ├── steering-examples.json
│   └── README.md                     #   安全 tier + handoff 说明
│
├── claude-for-msft-365-install/      # 独立工具:给 M365 add-in 做管理员部署(与 FSI 插件无关)
├── scripts/                          # 工具链:check.py / sync-agent-skills.py / version_bump.py / deploy / orchestrate
└── 投资建议/                          # 中文投研【产出物】(个股/行业分析),是数据不是代码
```

## 2.2 三类 plugin 的分工(记住这张关系)

| 类别 | 位置 | 是什么 | 关键点 |
|---|---|---|---|
| **vertical-plugins** | `plugins/vertical-plugins/<vertical>/` | 按业务线打包的 skill + command + 连接器 | **skill 的唯一源在这里**,改 skill 只能改这里 |
| **agent-plugins** | `plugins/agent-plugins/<slug>/` | 10 个端到端具名 agent,自包含 | 里面的 `skills/` 是同步来的**副本**,手改会被 CI 判 drift |
| **partner-built** | `plugins/partner-built/<partner>/` | 合作方(LSEG / S&P / china-market)贡献 | china-market 是唯一有 Python 服务的 |

三者之上还有 `managed-agent-cookbooks/`——它不是第四类能力,而是把 agent-plugins **换个壳**用于 API 托管部署(见 [05](./05-Managed-Agent与编排.md))。

## 2.3 一个 agent 同时存在于两处(务必建立这个心智)

以 `gl-reconciler` 为例,它在仓库里有**两副身体、一个大脑**:

```
plugins/agent-plugins/gl-reconciler/agents/gl-reconciler.md   ← 大脑(权威系统提示词)
        ▲ system.file 相对路径回指
managed-agent-cookbooks/gl-reconciler/agent.yaml              ← 托管部署的身体
plugins/agent-plugins/gl-reconciler/                          ← 插件形态的身体
```

`agent.yaml` 用 `system.file: ../../plugins/agent-plugins/gl-reconciler/agents/gl-reconciler.md` 指回同一个提示词文件(见 [agent.yaml:10-12](../managed-agent-cookbooks/gl-reconciler/agent.yaml#L10-L12))。这就是"一源两包装",详见 [03](./03-核心设计理念.md)。

## 2.4 "我要改 X 该去哪" —— 路径速查表

这是本书最实用的一张表。每一行的完整操作(改哪些文件 → 跑哪些脚本 → 怎么验证)在 [08](./08-如何修改与演进.md) 展开。

| 我想做… | 去这里改 | 之后必做 |
|---|---|---|
| 改 / 加一个 **skill** | `plugins/vertical-plugins/<vertical>/skills/<name>/SKILL.md`(**只改源**) | `python3 scripts/sync-agent-skills.py` → `python3 scripts/check.py` |
| 改 / 加一个 **slash command** | `plugins/vertical-plugins/<vertical>/commands/<name>.md` | `python3 scripts/check.py` |
| 新增一个 **具名 agent** | `plugins/agent-plugins/<slug>/` + `managed-agent-cookbooks/<slug>/` + 登记 marketplace.json | sync + check |
| 改 agent 的**行为 / 人格** | `plugins/agent-plugins/<slug>/agents/<slug>.md`(权威源,两形态共享) | check |
| 换 / 加**数据连接器**(第三方 MCP) | 对应插件的 `.mcp.json`(核心 11 个在 financial-analysis) | check |
| 给 A 股**加一个数据源** | `china-market/mcp_server/sources.py`(新 `DataSource` 子类)+ `config.yaml` 开关 | 跑 `test_data_layer.py`;CI 自动出镜像 |
| 给 A 股**加一个 MCP tool** | `china-market/mcp_server/server.py`(新 `@mcp.tool()`) | 同上 |
| **缓存 / 存储升级**(如换 Redis) | `china-market/mcp_server/cache.py`(实现新 `Cache` 子类) | server.py 注入点零改动 |
| 加一个**自动化 hook** | 对应插件的 `hooks/hooks.json`(当前多为空 `[]`,是现成挂点) | check |
| 调整 Managed Agent 的**工具 / 子 agent** | `managed-agent-cookbooks/<slug>/agent.yaml` + `subagents/*.yaml` | `scripts/test-cookbooks.sh` |

## 2.5 容易被误认的两个目录

- `投资建议/`:是 agent 跑出来的**中文投研产出物**(个股 / 行业分析 / 日报),属数据,不是代码,别当模块读。
- `claude-for-msft-365-install/`:独立的 IT 管理员工具,给 Microsoft 365 add-in 做租户部署(见 [README.md:137-148](../README.md#L137-L148)),**与上面的 agent / vertical 插件无关**,首次通读可跳过。
